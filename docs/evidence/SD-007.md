The stopped PostgreSQL PID was absent after failure. The same `EBUSY` then reproduced after a
successful Workflow run, proving that the shared Windows PostgreSQL cleanup path was the root
cause. The bounded correction uses Node's native recursive-removal retry in both the shared
runtime helper and the Stress-specific persistent cleanup while retaining an explicit error when
the retry bound is exhausted. A second Workflow diagnosis found a Windows process-exit race:
the child had emitted `exit`, but the subsequent best-effort `taskkill` lookup returned a stale
nonzero code. The correction treats the observed child `exit` as authoritative while still
failing if the child does not exit within the bound or if descendant locks prevent bounded
cleanup. Workflow was rerun at the same failed level before Stress, Build, Audit, and Elder
validation advanced. The final exact local ladder is rerun before commit.

The final ladder also exposed a cold-compile timing bound: the first desktop Workflow reached the
complete release-communication state but exhausted Playwright's implicit 30-second whole-test
timeout; the warm mobile path passed in 9.1 seconds. The explicit whole-test bound is now 60
seconds with retries still disabled, so a slow hosted cold start remains bounded and a real failure
is not hidden by retry.
