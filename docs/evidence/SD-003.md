## Product result

SignalDesk now lets a local owner approve exactly one immutable Implementation Brief for one
prioritized Product Issue. The UI and additive Signal-detail API expose:

- the bounded implementation objective;
- one to ten independently visible acceptance criteria;
- zero to ten constraints;
- an explicitly unverified local approver label and server approval time;
- exact Feedback, Signal, Signal revision, Product Issue, and Implementation Brief lineage.

The brief is created only through a locked PostgreSQL transaction. A unique foreign key and
database trigger reject a second brief, update, or deletion. The implementation adds no task
board, assignment, brief editing, model inference, authentication, hosted operation, merge,
deployment, release, or customer communication.
