## Verified Outcome

A local operator can use SignalDesk without database or terminal inspection to:

1. submit bounded feedback;
2. see the one canonical linked Signal;
3. inspect the source Feedback identifier and current revision;
4. append one manual triage event;
5. reload the application; and
6. observe the persisted state and ordered decision history.

The implementation preserves deterministic one-feedback-to-one-signal lineage. It does not group,
summarize, classify, prioritize, or infer.

## Implementation Evidence

- Next.js and TypeScript modular monolith with the accepted Feedback Intake and Signal Inbox
  boundaries.
- Prisma/PostgreSQL persistence with one transaction for Feedback and Signal.
- Database uniqueness for `Signal.feedbackId`.
- Database trigger preventing TriageEvent update or delete.
- Revision-predicate triage writes with one accepted winner under contention.
- Closed JSON objects, exact UTF-8 JSON media type, streaming 16 KiB request limit, Unicode
  code-point field limits, and explicit acknowledgement.
- Deterministic high-confidence credential and payment-card rejection.
- Operational desktop/mobile UI exposing source lineage and ordered history.
- Exact direct dependency versions and zero npm audit vulnerabilities.
