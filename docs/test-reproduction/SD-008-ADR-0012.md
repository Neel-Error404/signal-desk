execution, application-tree hashing, secret/forbidden-file scanning, vulnerability rejection, SBOM,

later digest-only deployment. One separate build supplies blocking application-tree equality and
advisory OCI config, manifest/layer, and final-digest diagnostics. Advisory mismatch suppresses a
reproducibility claim but is not, alone, a basic staging failure.

## Adapter evidence

```powershell
npm run sd008:artifact-adapter -- --format json
```

The adapter checks caller/callee permissions, known acyclic job dependencies, publication before
provision, Docker versus OCI exporter separation, required diagnostic output, and availability of
Docker, actionlint, and `jq`. When Docker exists, it performs a temporary local Docker daemon mutation
with verified cleanup: it reads the already pinned Node base-image digest from the project
`Dockerfile`, creates a uniquely named isolated Buildx builder, exports and runs a portable Node
probe, and removes the builder, image, and temporary context. Docker build steps use
`--network=none`, but builder bootstrap and pinned-base resolution may perform read-only registry
pulls. Builder and image
absence are accepted only after successful exact-name/reference Docker inventory queries;
daemon, transport, authorization, and other query errors fail the check. It performs no repository,
Git, registry-write, or provider mutation and never pushes, publishes, dispatches, or mutates GitHub,
GHCR, or Azure. The hosted review gate invokes this
executable path before Foundation.

`pass` means only the named local check ran successfully, including verified Docker cleanup when
Docker is present. `blocked` means a required executable is unavailable. Neither status proves GitHub workflow admission,
GHCR behavior, attestation acceptance, Docker build compatibility, or Azure behavior.
