publication or delivery authority.

## Observed failures and root causes

### Foundation contract assertion

The first Foundation run failed because the SD-005 test searched for an exact whitespace-aligned
Prisma field declaration. Adding the adjacent Release Communication relation changed Prisma's
alignment without changing the SD-005 field. The test was corrected to assert the field and
attributes semantically with a regular expression. The same Foundation level then passed.

### Elder lifecycle-chain reproduction

Current Elder accepted two individually valid lifecycle contracts even when the first contract's
`nextEligibleStage` did not equal the second contract's `lifecycleStage`, and the first outcome
record type did not equal the second source record type. A focused Component test reproduced the
missing fail-closed behavior. Elder was corrected to validate both adjacencies in registry order;
the same test and then the complete Elder ladder passed.

### Elder isolated-worktree environment

Activation initially rejected CRLF-transformed bytes for three digest-pinned research-source
artifacts. Normalizing those worktree copies to their registered LF-byte digests restored
activation without changing their content. Two pre-existing Component promotion tests then hit
the Windows path-length limit under the long worktree path. Moving the same registered worktree
to `D:\Balcony\elder-sd006` removed the environment-only failure; the complete Component level
passed there.
