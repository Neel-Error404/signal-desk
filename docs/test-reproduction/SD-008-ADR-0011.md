# SD-008 ADR 0011 Local Reproduction

**Status:** ADR 0011 RATIFIED; BOUNDED LOCAL IMPLEMENTATION IN PROGRESS

**Date:** August 22, 2026

## Claim under test

The rendered provision role assignment uses only Azure-supported delegated role-assignment
attributes, preserves the exact resource-group outer scope, restricts assignment targets to
non-provision service principals, and limits the delegated role to Key Vault Secrets User.

## Local reproduction

1. Render a packet with `scripts/render-sd008-azure-authority.mjs` and fixture UUIDs.
2. Inspect the provision assignment's `scope`, `conditionVersion`, and `condition`.
3. Require `RoleDefinitionId`, `PrincipalId`, `PrincipalType`,
   `ForAnyOfAllValues:GuidNotEquals`, and `ServicePrincipal`.
4. Reject `RoleAssignmentScope`, any role other than Key Vault Secrets User, a scope other than the
   exact fixture resource group, or a packet that applies mutation.
5. Verify the hosted workflow applies the same assertions to the live provider reread.
6. Run Foundation, Component, Integration, Workflow, and Stress in that order, stopping and fixing
   the same level before advancing if any level fails.

## Expected boundary

This procedure proves deterministic local rendering and assertion behavior only. It does not call
Azure, create a role assignment, validate provider acceptance, dispatch the workflow, or establish
that the condition ran successfully in a hosted session. Provider validation remains separately
gated.
