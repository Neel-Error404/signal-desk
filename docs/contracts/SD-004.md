# SD-004 Immutable Review Delivery Contract

**Version:** 1

**Status:** Ratified bounded implementation contract

**Change class:** `public-contract`

**Owner:** Neel

**Runtime boundary:** local-only product record plus product-owned Git delivery policy

## Contract claim

SD-004 lets a local product owner record one immutable, operator-supplied review delivery for one
approved Implementation Brief. It exposes the exact implementation-to-review trace without
claiming that SignalDesk or Elder independently verified GitHub.

## Review Delivery record

| Field | Contract |
|---|---|
| `id` | Server-generated UUID; immutable |
| `implementationBriefId` | Required source brief UUID; immutable and unique |
| `repositoryUrl` | Product-policy value `https://github.com/Neel-Error404/signal-desk`; immutable |
| `baseBranch` | 1 to 255 characters matching product base policy; immutable |
| `headBranch` | 1 to 255 characters matching product head policy and different from base; immutable |
| `commitSha` | Lowercase 40- or 64-character hexadecimal Git object identifier; immutable |
| `pullRequestNumber` | Positive integer parsed from the trusted pull-request URL; immutable |
| `pullRequestUrl` | Exact trusted prefix plus the same decimal PR number; immutable and unique |
| `verificationSummary` | 1 to 2,000 Unicode code points; immutable |
| `deliveredBy` | 1 to 120 Unicode code points; unverified local label; immutable |
| `deliveredAt` | Server-generated UTC RFC 3339 timestamp; immutable |

## `POST /api/v1/implementation-briefs/{implementationBriefId}/review-delivery`

Request:

```json
{
  "baseBranch": "work/sd-003-approved-implementation-brief",
  "headBranch": "work/sd-004-review-delivery",
  "commitSha": "0123456789abcdef0123456789abcdef01234567",
  "pullRequestUrl": "https://github.com/Neel-Error404/signal-desk/pull/3",
  "verificationSummary": "Foundation through Stress, build, audit, and Elder validation passed.",
  "deliveredBy": "Neel",
  "contentAcknowledged": true
}
```

The request is closed. All text is bounded and checked by the existing deterministic content
policy. Repository URL and PR number are derived from product policy and the trusted URL; clients
cannot supply or override the repository.

Success is `201 Created` with `reviewDelivery` plus complete Feedback-to-Brief lineage.

## Signal detail compatibility

`GET /api/v1/signals/{signalId}` retains SD-001 through SD-003 fields and adds
`reviewDelivery: null` or the serialized immutable Review Delivery.

## Error additions

| Status | Code | Condition |
|---|---|---|
| 404 | `implementation_brief_not_found` | The source brief does not exist |
| 409 | `review_delivery_exists` | The brief already has a delivery |

Invalid Git references use the existing `invalid_request` code. Storage and content failures use
the existing fail-closed errors.

## Product-owned Git delivery policy

`delivery/review-delivery-contract.json` is the machine-readable source for repository identity,
trusted PR URL prefix, branch rules, ordered checks, ship target, and authority boundaries.
Its optional `contextContracts` registry lists project-owned lifecycle contracts by relative
path. Referenced context remains descriptive and cannot grant execution authority.
Configuration is not proof that Git delivery occurred. Hosted provider evidence and P5.2
authority remain separate requirements.

## Non-claims

SD-004 does not verify GitHub, create or update a PR, store credentials, merge, deploy, release,
communicate with customers, authenticate users, or grant Elder L2/L3 authority.
