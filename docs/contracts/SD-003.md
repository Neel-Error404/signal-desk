# SD-003 Owner-Approved Implementation Brief Contract

**Version:** 1

**Status:** Ratified bounded implementation contract

**Change class:** `public-contract`

**Owner:** Neel

**Runtime boundary:** local-only

## Contract claim

SD-003 lets a local product owner approve one immutable Implementation Brief for one existing
Product Issue. The brief exposes objective, acceptance criteria, constraints, and complete
Feedback-to-Brief lineage through the product interface.

This contract does not provide authentication, verified identity, task execution, autonomous
pull-request creation, hosting, deployment, release, production readiness, or complete DLP.
All common SD-001 HTTP, content, privacy, correlation, and error-envelope rules continue to apply.

## Implementation Brief record

| Field | Contract |
|---|---|
| `id` | Server-generated UUID; immutable |
| `productIssueId` | Required source Product Issue UUID; immutable and unique |
| `objective` | 1 to 2,000 Unicode code points; immutable |
| `acceptanceCriteria` | 1 to 10 strings, each 1 to 500 Unicode code points; immutable |
| `constraints` | 0 to 10 strings, each 1 to 500 Unicode code points; immutable |
| `approvedBy` | 1 to 120 Unicode code points; unverified local label; immutable |
| `approvedAt` | Server-generated UTC RFC 3339 timestamp; immutable |

One Product Issue may have at most one Implementation Brief.

## `POST /api/v1/product-issues/{productIssueId}/implementation-brief`

Request:

```json
{
  "objective": "Preserve the selected date range when a report is exported.",
  "acceptanceCriteria": [
    "The exported report uses the date range visible at export time.",
    "Reloading the report does not change the previously exported artifact."
  ],
  "constraints": [
    "Do not change existing report retention behavior."
  ],
  "approvedBy": "Neel",
  "contentAcknowledged": true
}
```

Requirements:

- the request object is closed;
- objective, acceptanceCriteria, constraints, and approvedBy satisfy their declared bounds;
- `contentAcknowledged` is the literal boolean `true`;
- deterministic restricted-content checks run before persistence;
- the source Product Issue exists;
- no Implementation Brief already exists for that Product Issue.

Success is `201 Created` and returns the serialized `implementationBrief` plus lineage:

```json
{
  "implementationBrief": {
    "id": "uuid",
    "productIssueId": "uuid",
    "objective": "Preserve the selected date range when a report is exported.",
    "acceptanceCriteria": [
      "The exported report uses the date range visible at export time.",
      "Reloading the report does not change the previously exported artifact."
    ],
    "constraints": [
      "Do not change existing report retention behavior."
    ],
    "approvedBy": "Neel",
    "approvedAt": "2026-08-18T00:00:00.000Z"
  },
  "lineage": {
    "feedbackId": "uuid",
    "signalId": "uuid",
    "signalRevision": 2,
    "productIssueId": "uuid"
  }
}
```

## Signal detail compatibility

`GET /api/v1/signals/{signalId}` retains all SD-001 and SD-002 fields and adds:

```json
{
  "implementationBrief": null
}
```

or the serialized Implementation Brief. Existing clients may ignore this additive field.

## Error additions

| Status | Code | Condition |
|---|---|---|
| 404 | `product_issue_not_found` | The source Product Issue does not exist |
| 409 | `implementation_brief_exists` | The Product Issue already has a brief |

All SD-001 request, content, storage, and internal error codes remain applicable.

## Persistence and immutability

- Prisma is the only application database adapter.
- Eligibility and creation execute in one PostgreSQL transaction while the Product Issue row is
  locked.
- PostgreSQL enforces unique `ImplementationBrief.productIssueId` and its Product Issue foreign
  key.
- PostgreSQL checks array counts and a database trigger rejects invalid elements, update, or
  deletion.
- No SD-003 endpoint updates or deletes an Implementation Brief.

## Non-claims

SD-003 does not create tasks, assign implementation, track completion, verify a fix, create a
pull request, deploy, release, or communicate a change. The `reviewable-pr` target applies to
delivery of this product slice, not to Implementation Brief behavior.
