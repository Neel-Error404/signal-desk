# SD-006 Approved Unsent Release Communication Contract

**Version:** 1

**Status:** Ratified bounded implementation contract

**Change class:** `public-contract`

**Owner:** Neel

**Runtime boundary:** local-only owner-approved content; no publication capability

## Contract claim

SD-006 lets a local product owner approve one immutable Release Communication for one Completed
Fix while preserving exact source lineage. Approval does not mean the content was sent, published,
deployed, or released.

## Release Communication record

| Field | Contract |
|---|---|
| `id` | Server-generated UUID; immutable |
| `completedFixId` | Required source Completed Fix UUID; immutable and unique |
| `audience` | 1 to 500 Unicode code points; immutable |
| `subject` | 1 to 200 Unicode code points; immutable |
| `message` | 1 to 4,000 Unicode code points; immutable |
| `approvedBy` | 1 to 120 Unicode code points; unverified local label; immutable |
| `approvedAt` | Server-generated UTC RFC 3339 timestamp; immutable |

## `POST /api/v1/completed-fixes/{completedFixId}/release-communication`

Request:

```json
{
  "audience": "Customers who reported the affected workflow",
  "subject": "The reported workflow issue is fixed",
  "message": "We completed the reviewed fix. No action is required from you.",
  "approvedBy": "Neel",
  "approvalConfirmed": true,
  "contentAcknowledged": true
}
```

The request is closed. Approval confirmation and content acknowledgement must both be exactly
`true`. Text is bounded and checked by the deterministic content policy. Success is `201 Created`
with `releaseCommunication`, complete Feedback-to-Completed Fix lineage, and
`publicationStatus: "not-sent"`.

## Signal detail compatibility

`GET /api/v1/signals/{signalId}` retains all SD-001 through SD-005 fields and adds
`releaseCommunication: null` or the serialized immutable Release Communication. The response
also exposes `publicationStatus: "not-sent"` when the record exists.

## Errors

| Status | Code | Condition |
|---|---|---|
| 404 | `completed_fix_not_found` | The source Completed Fix does not exist |
| 409 | `release_communication_exists` | The Completed Fix already has a Release Communication |
| 422 | `release_approval_required` | Owner approval was not explicitly confirmed |

Malformed input uses `invalid_request`; storage and content failures retain existing fail-closed
errors.

## Non-claims

SD-006 does not send, publish, schedule, deploy, release, contact a customer, verify identity,
store provider credentials, or grant Elder lifecycle-transition or hosted delivery authority.
